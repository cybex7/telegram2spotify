# tg2spotify

**آیا توام این مشکل رو داری — کلی آهنگ تو یه کانال تلگرام داری که هیچ‌وقت به اسپاتیفای‌ت نرسیده؟**

این ابزار یک اکسپورت کانال تلگرام را می‌خواند، تگ‌های خراب اسم خواننده/عنوان
را درست می‌کند (اکسپورت تلگرام معروف است به به‌هم‌ریختگی: فیلدهای خالی،
جاعوض‌شدن خواننده و عنوان، اسپم کانال که توی خودِ اسم قاطی شده)، هر ترک را با
کاتالوگ واقعی اسپاتیفای تطبیق می‌دهد، و نتیجه را به یک پلی‌لیست اضافه می‌کند —
برای صدها ترک با هم، بدون این‌که حتی یک اسم را دستی تایپ کنی.

این ابزار روی یک آرشیو واقعی و به‌هم‌ریخته ساخته و تست شده: ۷۳۸ ترک، ۸.۵ سال
پست، موسیقی فارسی و بین‌المللی قاطی هم. ۶۴۲ تای آن‌ها (۸۷٪) کاملاً خودکار وارد
پلی‌لیست شدند. [داستان کامل را بخوان، همراه با هر باگی که داده واقعی نشان
داد ←](docs/ARTICLE.fa.md) ([English](docs/ARTICLE.en.md))

## آیا برای اجرای این به AI نیاز داری؟

**نه.** هر مرحلهٔ پایین یک اسکریپت پایتون معمولی است — regex، یک فرمول
شباهت، فراخوانی HTTP به اسپاتیفای. هیچ‌جای این کد با هیچ LLM حرف نمی‌زند، و
یک اجرای عادی همان دستورهای بخش «اجرا کن» پایین است، یا `./autopilot.sh`
برای کل کار بدون دخالت.

از AI (Claude) برای **ساختن** این ابزار و دیباگ‌کردنش روی یک کانال واقعی و
کثیف استفاده شد — داستانش در مقالهٔ بالا هست. تنها جایی که AI (یا کار دستی
regex) ممکن است برای *خودت* به کار بیاید: قاعده‌های تمیزکاری در `clean.py`
مخصوص کثیفی‌های همان یک کانال تنظیم شده‌اند. اگر کثیفی کانال تو شکل دیگری
دارد، ممکن است لازم باشد چند regex در همان یک فایل را گسترش بدهی — این یک
ویرایش یک‌باره است، نه پیش‌نیاز اجرای ابزار.

## چی لازم داری

- پایتون ۳ — بدون هیچ پکیج اضافه، فقط کتابخانهٔ استاندارد
- اکسپورت یک کانال تلگرام (از Telegram Desktop، فرمت JSON)
- یک اکانت رایگان Spotify Developer (۲ دقیقه، بدون کارت اعتباری)

## شروع سریع

### ۱. کانال تلگرام را اکسپورت کن

Telegram Desktop → کانال → منوی ⋮ → **Export chat history** → فرمت
**Machine-readable JSON**.

**اگر می‌شود، دانلود صدا را رد کن.** یک اسلایدر محدودیت حجم رسانه توی دیالوگ
اکسپورت هست — ببرش روی حداقل. همچنان اسم خواننده، عنوان، متن پیام، اسم فایل،
و (برای تقریباً همهٔ ترک‌ها) مدت‌زمان را می‌گیری؛ فقط از دانلود گیگابایت‌ها
صدایی که واقعاً لازم نداری صرف‌نظر می‌کنی. روی همین اجرای ۷۳۸ تایی اندازه
گرفتم: فقط ۱.۵٪ ترک‌ها واقعاً به خودِ فایل نیاز داشتند.

### ۲. یک اپ رایگان اسپاتیفای بساز

۱. برو به [developer.spotify.com/dashboard](https://developer.spotify.com/dashboard)
   و یک اپ بساز (هر اسم/توضیحی).
۲. **Redirect URI** آن را دقیقاً بگذار: `http://127.0.0.1:8888/callback`
۳. **Web API** را تیک بزن، ذخیره کن، و **Client ID** را کپی کن.

هیچ‌وقت به client secret نیاز نیست — این از PKCE استفاده می‌کند، که فقط
همان Client ID کافی است.

### ۳. ابزار را به هر دو وصل کن

```bash
echo YOUR_SPOTIFY_CLIENT_ID > .client_id
echo '/path/to/ChatExport_YYYY-MM-DD' > .export_path
```

هر دو فایل در gitignore هستند — هیچ‌وقت client ID را کامیت نکن. (از نظر
امنیتی یک راز نیست، ولی هرکس با آن اجرا کند سهمیهٔ جستجوی *تو* را خرج می‌کند
و وارث بن‌های محدودیت نرخ تو می‌شود.)

### ۴. اجرا کن

```bash
python3 tests/run_tests.py        # تایید می‌کند نصبت درست است: ۱۱۱ تست آفلاین
python3 run_ingest.py             # اکسپورت را می‌خواند، اسم‌ها را درست می‌کند، کاندیدای جستجو می‌سازد
python3 run_match.py 20           # اول ۲۰ ترک را با اسپاتیفای می‌سنجد، برای اطمینان
python3 run_match.py              # بقیه (هر وقت بخواهی دوباره اجرا کن، از همان‌جا ادامه می‌دهد)
```

اولین بار `run_match.py` یک‌بار اسپاتیفای را در مرورگرت باز می‌کند برای یک
کلیک تایید. بعدش دیگر ساکت است.

### ۵. به یک پلی‌لیست بفرست

```bash
python3 run_push.py "اسم پلی‌لیست من" "<playlist-id-یا-لینک>" --include-review
```

یک پلی‌لیستی که از قبل ساخته‌ای بده (لینک اشتراک‌گذاری یا آیدی‌اش را بچسبان) —
ابزار تطبیق‌ها را به آن اضافه می‌کند و هیچ‌وقت یک ترک را دوباره اضافه نمی‌کند،
حتی اگر دوباره اجرایش کنی. `--include-review` ترک‌هایی را هم منتشر می‌کند که
تطبیق‌دهنده کاملاً مطمئن نبود (پایین‌تر ببین «آن‌هایی که مطمئن نیست»)؛ بدون
این فلگ فقط تطبیق‌های مطمئن منتشر می‌شوند.

### ۶. نتیجه را چک کن

```bash
python3 status.py       # یک خلاصهٔ تک‌صفحه‌ای: تطبیق‌شده / نامطمئن / پیدانشده
python3 run_audit.py    # یک CSV از هرچیزی که ارزش یک گوش‌دادن دستی را دارد
```

## بیشتر از چند صد ترک داری؟

سهمیهٔ جستجوی اسپاتیفای بعد از چند صد درخواست تمام می‌شود و چند ساعت بعد
برمی‌گردد. به‌جای این‌که مرحلهٔ ۴ و ۵ را هر بار که سهمیه باز شد دستی اجرا کنی،
بگذار خودش مدیریتش کند:

```bash
nohup ./autopilot.sh "اسم پلی‌لیست من" "<playlist-id>" --include-review &
```

هر چقدر می‌تواند تطبیق می‌دهد، push می‌کند — و اگر سهمیه تمام شد، دقیقاً
به‌اندازه‌ای که اسپاتیفای خواسته می‌خوابد، بعد خودش دوباره شروع می‌کند. با
Ctrl-C قطعش کن و هر وقت خواستی دوباره اجرا کن؛ تا وقتی همهٔ ترک‌ها حل نشوند
ادامه می‌دهد. `nohup` یعنی حتی با بستن ترمینال هم زنده می‌ماند.

## آن‌هایی که پیدا نمی‌کند

بعضی ترک‌ها واقعاً در اسپاتیفای نیستند — ریمیکس، ضبط زنده، آپلود غیررسمی.
این‌ها در `reports/not_found.csv` می‌افتند، هر ردیف با یک لینک آمادهٔ
`open.spotify.com/search/...` — کلیک کن، چک کن، اگر واقعاً بود دستی اضافه‌اش
کن.

## آن‌هایی که مطمئن نیست

`run_audit.py` فایل `reports/suspects.csv` را می‌نویسد: هر ترکی که پیدا
نشد، هر ترکی که با وجود نامطمئن‌بودن منتشر شد، و هر تطبیق خودکاری که امتیازش
روی مرز بود. قبل از این‌که کامل به پلی‌لیست اعتماد کنی ارزش یک گوش‌دادن سریع
را دارد — تطبیق بر اساس متن و مدت‌زمان خوب است، نه بی‌عیب (یک کاور
نُت‌به‌نُتِ یک خوانندهٔ دیگر می‌تواند گولش بزند؛ در مقاله یک مثال واقعی هست).

## بدون هیچ وابستگی، عمداً

فقط کتابخانهٔ استاندارد پایتون، بدون هیچ `pip install`. `difflib` جای
`rapidfuzz` را می‌گیرد، `urllib` جای `requests`، و `src/tg2spotify/id3.py`
یک خوانندهٔ کوچک دست‌نویس ID3 است به‌جای `mutagen`.
